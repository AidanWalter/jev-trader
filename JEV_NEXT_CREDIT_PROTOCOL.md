# Jev next-credit protocol

This project will not distill Jev, train a surrogate to make Jev's decisions, or substitute an ML decision model for Jev. The paid path uses Jev's direction probability distribution as the sole predictive signal. Position sizing, abstention, exposure caps, execution simulation, and portfolio allocation are deterministic policy logic around Jev's probabilities.

The fixed research universe is BTCUSDT, ETHUSDT, and SOLUSDT on one-hour bars from 2024-01-01 through 2026-09-01. The paid apparatus is fixed at an eight-bar forecast horizon, an eight-bar decision cadence, the compact `lean` state profile, and the `jev-direction` evaluator. Paid workflows check out audited research commit `9c7ae2796ea6c7e01a59522177b150e8c99c34c2`. No paid stage is permitted to vary horizon, profile, cadence, prompt, or model after billing begins.

The paid sequence is `jev-direction-canary`, then `jev-direction-sample-48`, then `jev-direction-sample` for 240 total states, then `jev-direction-sample-1000`, then `jev-direction-development`, then `jev-direction-sealed`. Every stage is manual-only. The Jev secret is scoped only to the step that actually calls Jev. Paid calls run serially with concurrency one and the direction evaluator has no automatic retry loop.

The first canary contains twelve fresh states and has a lifetime ceiling of twelve requests, 30,000 input tokens, and $0.0015. The 48-state expansion can add at most thirty-six fresh requests under 80,000 input tokens and $0.004. The 240-state expansion can add at most 192 fresh requests under 384,000 input tokens and $0.017. The 1,000-state expansion can add at most 760 fresh requests under 1,520,000 input tokens and $0.065. The development expansion can add at most 5,996 fresh requests under 11,992,000 input tokens and $0.505. The sealed tail can add at most 1,752 fresh requests under 3,504,000 input tokens and $0.15. With a 2,000-token reservation per request, the zero-call readiness rehearsal computes a worst-case reserved total of 17,496,000 input tokens and $0.734832 for the entire staged research path.

The samples are strictly nested. The first twelve selected states are the prefix of the 48-state sample, the first 48 are the prefix of the 240-state sample, and the first 240 are the prefix of the 1,000-state sample. The development stage requires those 1,000 answers to be cache hits. Successful prior calls therefore are never intentionally repurchased.

After each paid stage, the next stage requires the exact TypeSafe dashboard request-count delta and input-token delta. The request count must exactly match the artifact's recorded request count. Input tokens must reconcile within the narrow tolerance encoded in the workflow. If the dashboard does not reconcile, the sequence stops. A failed stage may only resume from its saved partial cache after the failed attempt's actual TypeSafe dashboard usage is supplied. The remaining request and token allowance is subtracted from the original lifetime cap, so restarting GitHub never creates a new budget.

Signal gates become stricter as sample size grows. The 240- and 1,000-state stages require direction probabilities to beat a uniform-probability Brier baseline, enough non-flat decisions, positive cost-adjusted called-side returns in multiple chronological quartiles and symbols, and minimum high-confidence or high-edge sample counts. Development uses no additional model or ML predictor. It tunes only deterministic policy thresholds against cached Jev probabilities, then requires positive validation returns under nominal, 1.5x, and 2x modeled costs and positive chronological validation segments before freezing.

The sealed period is never used for tuning. It can run only after a qualified frozen development apparatus and independent validation audit exist. The sealed workflow is one-time, manual, dashboard-gated, lifetime-capped, and resumable only from its own partial cache with provider billing reconciliation.

Legacy paid workflows are retired and hard-disabled. `jev-workflow-safety` audits every workflow that can see `TYPESAFE_AI_API_KEY` and fails if an unapproved workflow is not hard-disabled, if an approved paid workflow acquires an automatic trigger, exposes the secret at job scope, loses its pinned research commit, removes serial execution, removes its explicit spend cap, or changes the aggregate staged ceiling above $0.75. `jev-zero-call-readiness` rehearses the fixed market/reference artifacts and nested sampling without making any Jev calls.

Forward paper trading remains separate from research spend. The frozen Binance portfolio paper runner persists lifetime Jev request and input-token usage in its state file, refuses paid mode without `--confirm-paid=true`, and applies a lifetime spend ledger across restarts. No real exchange order placement is part of this protocol.
